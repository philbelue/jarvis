02 — Hermes Auto-Threading on @Mention Fix Ready

● Before State

When a user types @Hermes in a Discord channel, the bot creates a new thread and replies inside it. The user expects an in-channel reply, like how OpenClaw (Jarvis) responds. This fragments conversations and buries responses.

// Current behavior (pseudocode)
on message mentioning Hermes:
  thread = message.create_thread()
  thread.send(response)

● Target State

Hermes replies directly in the channel where it was mentioned, matching OpenClaw's behavior. No thread creation on @mention. Conversations stay visible and in-context for all channel participants.

// Fixed behavior (pseudocode)
on message mentioning Hermes:
  message.channel.send(response)
  // or message.reply(response)

03 — Hermes / OpenClaw Identity Clarification Resolved

● Before State

No documented distinction between the two Discord bots. Cortex lists them as separate services but their relationship and separate roles were unclear from the dashboard alone. Could be mistaken for one bot with two names.

● After State

Confirmed: Hermes (Hermie) and OpenClaw (Jarvis) are two distinct Discord bots running as independent services. Each has its own service ID, codebase, and bot tag. Watchdog monitors both independently. This is now documented in session memory.
