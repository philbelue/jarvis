Hard Rules — Tape to the Wall

Rule 01
Never use Opus via API. Ever.
Opus reasoning is for Cowork (flat subscription). API-tier Opus is a $0 line item.
Rule 02
Sonnet in Jarvis is restricted to 3 channels.
#thinking, #jarvis-strategy, #jarvis-builds. Everywhere else is Gemini Flash or Mistral.
Rule 03
Webhook channels don't get a Jarvis reply.
requireMention: true on every brief/recap channel. n8n posting there shouldn't trigger a billable call.
Rule 04
No confidence claims without a functional test.
"The config looks right" is not "it's working." Actually ping the bot. Actually see the response.
Rule 05
"Log it" ≠ "Ship it."
"Log it" writes to agent-log.md. "Ship it" executes and tests. Never conflate.
Rule 06
Daily cost report to #arc-reactor at 11pm.
Hermes posts MTD spend + delta-today. You catch $286 bleeds on day 2, not day 7.

Why The $286 Happened (one-pager)

So you never have to diagnose this again.

  1. Default model was Sonnet. claude-sonnet-4-6 was set as the fallback in openclaw.json. Any channel without an explicit override inherited Sonnet.
  2. Only 4 channels had overrides. The 4 automation channels were correctly routed to Gemini Flash. Every other channel — including your main chat channels and webhook destinations — silently used Sonnet.
  3. requireMention was false guild-wide. That meant every single message in every un-overridden channel triggered a Sonnet call — including webhook posts, Hermes status pings, and your own typing.
  4. Briefs channels doubled the bleed. n8n posts a brief to #ixon-morning-brief. Jarvis sees the message. Jarvis (on Sonnet) generates a response. Paid twice.
  5. Heartbeats probably on Sonnet too. If the health-probe cron was using the default model, that's a billable call every 30 min, 24/7, at Sonnet rates. (Confirm in Claude Code — check heartbeat_model key.)
