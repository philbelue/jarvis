Apex — The Command Layer

You live at the top. The apex is the decision point where you pick a path before you touch a keyboard. Every interaction is filtered through three questions — that's it. The rest of this doc is the territory that each question opens into.

Question 1
Which Surface?

Chat, Cowork, Claude Code, or API. Get this wrong and you waste 10× the effort.

Question 2
Which Model?

Opus for strategy and one-of-a-kind work. Sonnet for bulk execution. Haiku for speed and routing.

Question 3
Which Pattern?

One-shot, agent loop, skill-driven, or scheduled. The shape of the work dictates the tool.

Mental Model

Treat Claude as an operator you dispatch work to — not a chatbot you converse with. You define outcome, constraints, and format. It executes. You verify. That flip is the entire game.

Landscape · Surfaces

Four primary surfaces. Pick by the shape of the work, not by habit.

Cowork — Your Cockpit

What it is: Desktop app with native Mac control, file access, cross-app automation, skills, plugins, MCPs. It's what you're using right now.

When to use: File operations on your Mac, anything Jarvis-adjacent, HTML/doc creation, desktop workflows, Notes/Finder/Mail manipulation, running skills and scheduled tasks.

Killer feature: Skills — reusable instruction bundles (Jarvis Midnight theme, pptx, docx) that auto-trigger on keywords and produce on-brand output every time.

Your default. 70% of your time lives here.

Claude Code — Your Forge

What it is: CLI tool for agentic coding inside your terminal. Sees your codebase, runs commands, edits files, commits to git.

When to use: Building Jarvis itself. Repo work. Version-controlled infrastructure. Anything where the source of truth is a git repository.

Killer feature: Autonomous multi-step coding — plan, edit, test, verify, commit in one loop. Hooks and subagents for custom workflows.

Rule of thumb: If the work ends in a git commit, it belongs here.

Chat (claude.ai / Desktop) — Your Scratchpad

What it is: Pure conversation. Web app at claude.ai and the desktop app. No file tools, no computer control (unless inside Cowork mode).

When to use: Thinking, strategy, drafting, research, tutoring, creative work. Whenever the deliverable is an answer, not an artifact on your machine.

Killer feature: Projects — persistent context (custom instructions + files) across conversations. Artifacts — live HTML/React/markdown previews.

Rule of thumb: If you could do it on a whiteboard, do it here first. Then move to Cowork/Code to execute.

API + Agent SDK — Your Autopilot

What it is: Programmatic access to Claude. Build custom agents, automations, batch jobs, integrations that run without you.

When to use: When something needs to run on a trigger, a schedule, or across thousands of inputs. When you want Claude embedded in software you own.

Killer feature: The Agent SDK — same harness that powers Claude Code, available as a library. Build your own Jarvis agents on top of it.

Rule of thumb: If you'd ever run this workflow more than 10 times, graduate it to the API.

Claude in Chrome + Mobile — Edge Surfaces

Chrome: Browser extension that lets Claude see the DOM, click, fill forms, scrape pages. Much faster than computer-use pixel clicking for web tasks.

Mobile: Capture-and-queue. Voice notes, photos, quick questions. Not your execution surface — your inbox.

Both: Use when the input is where the action is (browser or phone), but don't mistake them for your primary cockpit.

Landscape · Models

Three models, three jobs. Pick by decision-stakes × volume.

Model Role Use For Don't Use For
Opus 4.7 Flagship reasoning Strategy, architecture, one-of-a-kind work, hard debugging, this document Routine formatting, bulk classification, simple lookups
Sonnet 4.6 Balanced execution Most daily work, code execution, document production, research synthesis Trivial routing; novel architectural decisions
Haiku 4.5 Speed + volume Agent routing, classification, cheap subagents, quick summaries Anything requiring deep reasoning or creative work
Cost-Leverage Rule

Use Opus to design the system, Sonnet to run the system, Haiku to route inside the system. In a Jarvis multi-agent setup, Opus is the architect, Sonnet is the worker pool, Haiku is the dispatcher.

Mastery · Prompting

The output quality is a function of the input structure. This is the reusable stack.

The 4-Layer Prompt Stack

ROLE     // You are [X]. Strategic framing.
CONTEXT  // What exists, what you tried, constraints.
TASK     // The specific outcome. Be literal.
OUTPUT   // Format, length, structure, constraints on style.

High-Leverage Techniques

Examples > Description

One positive example + one negative example beats a paragraph of description. "Like this, not like that."

XML Tags for Structure

Wrap sections in <context>, <task>, <examples>. Claude parses them cleanly and never confuses them with content.

Constraints > Preferences

"Must be under 300 words" beats "keep it short." "Only use Tailwind utility classes" beats "make it clean."

Force the Outcome

End with the format: "Output as a numbered list of 5 items, each under 20 words." Ambiguity kills quality.

When Stuck

The 3 Debug Moves

1. Say what bad looks like. Give Claude an example of the wrong answer it just gave and name what's wrong.
2. Add a constraint, not another instruction. "Under 100 words" > "be concise."
3. Make it think first. "Before answering, list your assumptions" forces reasoning to surface.

Mastery · Workflow Loop

The 4-phase loop that applies to virtually every non-trivial task.

Phase 01
Research

Gather: read files, search the web, check the codebase, check state. Never build on an assumed premise.

Phase 02
Plan

Write a TodoList or outline before acting. The act of writing the plan surfaces edge cases.

Phase 03
Execute

Do the work. One todo in-progress at a time. Mark complete only when actually done.

Phase 04
Verify

Spot-check the output. Run tests. Spawn a subagent for independent review on high-stakes work. Ship only after verification.

The Verify Move

For anything above a one-shot: spawn a second Claude to review the output without the original context. An independent pair of eyes catches what the author missed — even when the author is an LLM.

Mastery · Systems Thinking

The meta-rule: work on the system, not in the system.

Build Infra When…
  • You've done the task 3+ times
  • The output shape is stable
  • Someone else could benefit
  • The task gates other work
One-Shot When…
  • It's a one-of-a-kind
  • The shape is unknown
  • You're exploring
  • The constraint is time, not repetition
The Leverage Test

Before building infra, ask: will this save me 10× the time I'm about to invest? If yes, build. If no, one-shot and move on.

Cost-to-Value

Opus on strategy (rare, high-stakes). Sonnet on execution (daily). Haiku on routing (constant, cheap). Never use Opus where Haiku would work.

The Prompt Stack

Pin this. Paste it as a template. Fill the four slots. Ship.

ROLE: You are my [strategic operator / systems architect / research analyst / code reviewer].
      Your job is to [primary outcome].

CONTEXT:
- What exists: [current state, files, stack]
- What I've tried: [prior attempts, what failed]
- Constraints: [budget, time, tech, style]

TASK:
[Specific, literal outcome. One sentence.]

OUTPUT:
- Format: [markdown / HTML / code / table / list]
- Length: [word or item count]
- Tone: [operator / academic / casual]
- Must include: [required elements]
- Must NOT: [anti-patterns]
Why it works

ROLE sets the lens. CONTEXT prevents invented premises. TASK removes ambiguity. OUTPUT locks the shape. Skip any one slot and quality degrades predictably.

Picked the right model. Opus for strategy, Sonnet for execution, Haiku for volume.

6-Week Mastery Ladder

Your learning path. One rung per week. Don't skip — each one compounds on the last.

Week 01
Master the Prompt Stack

Every prompt uses ROLE / CONTEXT / TASK / OUTPUT. No exceptions. Feel the quality jump.

Week 02
Live in Cowork

Move recurring desktop/file work from Chat to Cowork. Let skills auto-fire. Pin this doc.

Week 03
Build Your First Skill

Pick a recurring output you produce. Codify it using the skill-creator skill. Watch it auto-trigger.

Week 04
Ship a Scheduled Task

Morning brief, weekly audit, daily Jarvis status. Something that runs without you even opening the app.

Week 05
Package a Plugin

Bundle your skills + MCPs + settings into a Jarvis plugin. Installable. Versioned. Shippable.

Week 06+
Architect a Multi-Agent System

Agent SDK. Opus orchestrator, Sonnet workers, Haiku router. Jarvis stops being a tool and becomes infrastructure.
