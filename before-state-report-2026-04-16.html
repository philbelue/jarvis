Executive Summary

At 6:00 PM on April 16, 2026, Jarvis — the local AI infrastructure running on a Mac Studio — was simultaneously expensive, slow, and ignorant. Four independent failures had compounded across the stack, each one hidden by the next, creating a system that looked operational from the outside but delivered degraded value while burning $286 per week in API costs.

The failures were not random bugs. They were layered infrastructure drift — each one rooted in a config default that was never audited. The operator was absorbing the cost manually: re-providing context to Jarvis on every session, tolerating 15-second memory lookups, and paying premium Sonnet rates for tasks that should have routed to free local models.

This document captures the baseline state so that tonight's repairs — and the 30-day benchmark that starts from here — have a fixed reference point.

Core Finding

Jarvis had no awareness of the Obsidian vault — the file system treated as the canonical source of truth by CLAUDE.md. Every prior "why doesn't Jarvis remember X?" frustration traces back to this single scope error. The memory layer was indexing 18 self-written session files, not the knowledge base.

The Four-Layer Architecture

Jarvis is conceptually a four-layer stack. Each layer depends on the one below it being stable. On April 16 evening, three of the four layers had compounding issues — which is why building upward (new automations, new agents, new workflows) kept producing disappointment. The foundation was wet concrete.

Rule

You cannot amplify what is broken. L4 automations firing against L1/L2 failures don't produce automation — they produce faster and more expensive failure. This is the principle that explains why adding more n8n workflows over the prior weeks made the problem feel worse, not better.

The Four Failures

Each of the following was a distinct, shippable-in-isolation bug. Their compounding effect — not any individual one — was what made the system feel fundamentally broken.

P0
Default Model Routing Bleed
~$286 / week
Symptom

Any Discord channel not explicitly routed in the OpenClaw config was defaulting to anthropic/claude-sonnet-4-6. This meant every internal reference channel, every side-thread, every forgotten workflow was paying Sonnet rates for Sonnet-tier tasks that should have been Gemini Flash jobs at zero cost.

Root Cause

In ~/.openclaw/openclaw.json, agents.defaults.model.primary was set to Sonnet. The config had been authored conservatively — defaulting to the strongest model — without a later pass to demote the default once routing rules matured.

Phil was funding every unrouted message out of the same budget intended for deep thinking work in #thinking. This is the classic "1% of traffic = 90% of spend" leak — except the 1% was unmonitored channels generating background cruft.

P1
Active-Memory Plugin Prefix Bug
100% 404 rate
Symptom

Every active-memory subagent call returned FailoverError: Unknown model: openai/mistral-small3.1. Mistral is an Ollama-hosted local model. It is not an OpenAI model. Nothing should have been attempting to route it through OpenAI.

Root Cause

The plugin used parseModelRef(configured, DEFAULT_PROVIDER). When the configured model string was bare mistral-small3.1 (no provider prefix), parseModelRef auto-prefixed it with DEFAULT_PROVIDER, which was hardcoded to openai in defaults.ts:3. Result: openai/mistral-small3.1, which OpenAI legitimately returns 404 for.

Every memory recall call was failing silently with a fallback summary. The user perceived "Jarvis can't remember things" — the actual cause was Jarvis was never successfully calling the summarizer model because the routing was broken before the call even left the machine.

P1.6
Memory in FTS-Only Mode
15s p95 latency
Symptom

Every memory query hit a 15-second timeout. Warning messages in the gateway log stated sqlite-vec unavailable. Operator response: "I've been fighting this for weeks."

Root Cause (Inverted from Initial Theory)

The warning message was misleading. sqlite-vec was installed correctly at ~/openclaw/node_modules/sqlite-vec-darwin-arm64/vec0.dylib. The actual cause was that agents.defaults.memorySearch.provider was unset — no embedding provider was configured, so OpenClaw ran in FTS-only mode and never generated embeddings at all.

The chunks_vec table was never created. The error message said "sqlite-vec unavailable" when the true state was "no embeddings have ever been generated." Every memory query fell back to full-text keyword scan across 30K+ character MEMORY.md plus 17 dated session files.

Implication

Vector search — the core mechanic that makes an LLM assistant usable at scale — was not operational. The 156 memory chunks had embedding_bytes: 2 (empty) instead of the expected ~16KB per 768-dimensional float vector. The system had been paying the cost of maintaining a vector schema without ever populating it.

P1.10
Vault Not in Indexed Sources
0% vault recall
Symptom

When Jarvis was asked "what did we ship in the last hour?" in Discord, he responded: "I don't have visibility into a code deployment pipeline or git log from this session." He could not recall recently shipped work.

Root Cause (the deepest one)

OpenClaw's memory was indexing a single directory: ~/.openclaw/workspace/memory/. This contained 18 files — all of them Jarvis's own self-written daily session flushes. The Obsidian vault at /Volumes/Jarvis/obsidian-vault/ — which CLAUDE.md explicitly designated as the canonical source of truth — was never in the indexed paths.

Every note written to the vault for months, including the priority queue, the benchmark tracker, and all session working context, was invisible to Jarvis. He had no mechanism to recall it.

The Delivery Problem

Every broken component — the $286 bleed, the 15-second lag, the missing vault index, the prefix 404s — routed the same damage to the operator: more things to remember, monitor, or manually correct. The compounding effect was burnout pressure at rising quota attainment.

What Jarvis Should Have Been Doing

Design Principle (Post-Reframe)

Agents do not deliver information. They deliver decisions-already-made or actions-already-taken. If an output arrives and the operator's reaction is "yeah I know" — the system failed. The only things that should cross the attention threshold are (a) judgment calls, (b) confirmations before irreversible action, (c) genuinely new signal.

What Jarvis Was Actually Doing

Observed Behavior

Posting briefs to Discord channels the operator did not watch. Drafting emails that sat in the inbox adding to the "to review" pile. Generating task summaries that duplicated mental state the operator already carried. Busywork with an AI veneer.

The Reframe — From Cost-Minimization to Value-Maximization

Mid-session, Phil issued a reframe that changed the entire decision framework:

"Cost and quality = VALUE for me. Value = time saved, stress reduced, ability to earn more. This is capital ex to buy more capital and financial freedom." — Phil Belue, 2026-04-16

The New Decision Framework

Equation

VALUE = (time saved) + (stress reduced) + (earning capacity unlocked) − (direct cost)

This is not a cost-minimization problem. Picking the cheapest option is wrong if the cheap option fails to deliver time-saved or stress-reduced. Picking the expensive option is wrong if a local equivalent delivers the same outcome. The answer is always: benchmark the cheap option first, upgrade only if it fails.

Why This Matters For The Infrastructure

The prior $6,000 in Mac Studio investment was capex for precisely this purpose — to enable local-first, zero-marginal-cost compute for everything that can run locally, freeing cloud budget for the specific thinking tasks where frontier-model quality pays for itself. The before-state violated this principle in two directions at once: paying cloud Sonnet rates for things that should have been local, while failing to extract value from the local compute that was already paid for.

What Shipped Tonight

Six separate fixes, each surgical, each verified. The pattern: every bug was already fixable with existing software — the problem was that misconfiguration hid the real state.

cost

Default Model Flipped — Sonnet → Gemini Flash

Fix: Changed agents.defaults.model.primary from anthropic/claude-sonnet-4-6 to openrouter/google/gemini-2.0-flash-001. Hotfix (P0.1): corrected model ID suffix after first boot failure.

Impact: Any channel not explicitly routed to Sonnet now costs fractions of a cent per response instead of Sonnet rates. Projected weekly burn dropped from ~$286 → ~$30.

P1 · SHIPPED
provider

active-memory Provider Prefix

Fix: Changed plugin config from bare mistral-small3.1 to ollama/mistral-small3.1 — OpenClaw was defaulting missing-prefix models to OpenAI, producing 404s on every memory query.

Impact: Background memory subagent now routes to local Ollama correctly. Zero 404s post-fix.

P1.6 · SHIPPED
memory

Vector Embeddings — FIRST TIME EVER WORKING

Fix: Added memorySearch: { provider: "ollama", model: "nomic-embed-text", fallback: "none" } to openclaw.json. Pulled nomic-embed-text (274 MB, 768-dim). Reindexed 156 chunks in 6 seconds.

Impact: OpenClaw stopped running in FTS-only (keyword) mode. chunks_vec table now populated, all chunks have embeddings. Memory does real vector similarity search. 30-day benchmark running — review 2026-05-16, upgrade to voyage-3-large if metrics miss.

P1.10 · SHIPPED
scope

Vault Path Indexed

Fix: Added extraPaths: ["/Volumes/Jarvis/obsidian-vault/02-NOW"] to memorySearch. Force-reindex took 6s. Index grew from 156 → 162 chunks. Watcher confirmed auto-indexing within 30s on new files.

Impact: Every vault note in 02-NOW is now searchable. Specific query "P1.6 SHIPPED memory FTS-only" returns priority-queue.md at score 0.750 (top result). Vault is now a first-class memory source.

P1.8 · SHIPPED
behavior

Memory-First Reflex — The Real Unlock

Fix: Prepended MEMORY-FIRST PROTOCOL block to ~/.openclaw/workspace/AGENTS.md (priority 10, first injected file). Block enumerates trigger phrases, forbids punting before tool call, and explicitly overrides the 129-char active-memory auto-summary as "a hint, not an answer."

Impact: Sonnet now calls memory_search reflexively on recall questions instead of answering "I don't know." Verified end-to-end in #jarvis-builds: Jarvis returned accurate ship log for P0/P1/P1.6/P1.10 with P0.1 hotfix detail. This is the bug that unlocked everything else.

Architectural Insight

The four original failures plus P1.8 formed a dependency chain: routing (P0) → providers (P1) → embeddings (P1.6) → scope (P1.10) → reflex (P1.8). Each one masked the next. Fixing them in order was the only sequence that worked — shipping P1.8 first would have revealed no memory to search, shipping P1.10 first would have indexed into a broken embedding pipeline. The dependency chain defined the shipping order.
